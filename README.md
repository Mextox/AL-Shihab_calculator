# 🌠 حاسبة الشهاب

تطبيق ويب لحساب تمويل السيارات لدى **الشهاب لاستيراد السيارات**، بواجهة
عربية حديثة وتخزين مشترك عبر Firebase.

## ✨ المميزات

### 💼 الحاسبة المالية
- حساب الأقساط الشهرية بدقة
- تطبيق قاعدة نصف المرتب لحماية العميل
- حساب هامش الربح (عادي ومخفض)
- إتاحة مدة التمويل حسب المرتب مع بيان المرتب اللازم لكل مدة
- عرض النتائج بشكل تفصيلي ومرئي
- تحذيرات ذكية للمعاملات غير المجدية

### 📐 المعادلات الأساسية

```
عدد الأشهر          = المدة بالسنوات × 12
نسبة الربح الإجمالية = (النسبة السنوية × عدد السنوات) ÷ 100
السعر النهائي        = سعر السيارة × (1 + نسبة الربح الإجمالية)

القسط الشهري:
  إذا السعر النهائي ≤ سقف المرابحة → السعر النهائي ÷ عدد الأشهر
  وإلا                              → سقف المرابحة ÷ عدد الأشهر
  ثم إذا تجاوز نصف المرتب           → نصف المرتب

مجموع الأقساط  = القسط الشهري × عدد الأشهر
دفعة المصرف    = السعر النهائي − مجموع الأقساط
صافي العميل    = سعر الإغلاق − دفعة المصرف
خسارة العميل   = السعر النهائي − سعر الإغلاق

تفاصيل البنك:
معامل الربح               = 1 + نسبة الربح الإجمالية
الدفعة المطلوب إدخالها     = ⌊ دفعة المصرف ÷ معامل الربح ⌋
باقي الدفعة (للربح)        = دفعة المصرف − الدفعة المطلوب إدخالها
تمويل المرابحة            = سعر السيارة − الدفعة المطلوب إدخالها
القسط بدون هامش الربح      = تمويل المرابحة ÷ عدد الأشهر
```

هامش الربح **بسيط تراكمي** لا مركّب: 3% على 8 سنوات تساوي 24% لا (1.03)⁸.
ومعامل الربح يتبع المعاملة تلقائياً — 3% × 8 سنوات = 1.24، ومع التخفيض
2% × 8 سنوات = 1.16.

### ⏳ قاعدة إتاحة مدة التمويل

```
المدة متاحة  ⟺  (المرتب ÷ 2) × (السنوات × 12)  ≥  المبلغ المطلوب
```

المبلغ المطلوب هو **سقف المرابحة** قبل إدخال سعر السيارة، ثم يصبح **الأقل بين
السعر النهائي للسيارة والسقف** بعد إدخاله — فتنفتح المدد القصيرة للسيارات
الرخيصة. ومدة 8 سنوات (الحد الأقصى) متاحة دائماً مهما كان المرتب.

مثال: مرتب 2500 د.ل ← نصفه 1250 × 96 شهراً = 120,000 = السقف بالضبط،
فتتاح 8 سنوات فقط. وبمرتب 3000 تُفتح 7 سنوات أيضاً (1500 × 84 = 126,000).
والمدد المغلقة تظهر في القائمة مع المرتب المطلوب لفتحها.

### 🚙 إدارة السيارات
إدارة السيارات موجودة **داخل لوحة الإعدادات** فلا يراها إلا المسؤول.

- إضافة وتعديل وحذف السيارات مع سعر الشراء وسعر الإغلاق
- سعر إغلاق **ثابت أو نطاق من – إلى** لكل سيارة
- صورة لكل سيارة: بحث تلقائي عن صور الموديل، أو رفع صورة من الجهاز
- الصور المختارة تُنسخ إلى Firebase Storage فلا تنكسر روابطها

وفي الحاسبة يظهر **منتقي السيارة** بجانب سعر الشراء: تختار سيارة محفوظة
فيمتلئ سعرها وسعر إغلاقها وتظهر صورتها، أو تتركه على «إدخال يدوي».
وأي تعديل يدوي على السعر يلغي الاختيار تلقائياً.

### 📊 سعر الإغلاق كنطاق
عند اختيار نطاق `من – إلى` تتحول ثلاث نتائج إلى نطاقات:
**صافي العميل** و**خسارة العميل** و**نسبة الخسارة**. أما القسط الشهري
ودفعة المصرف فلا يتأثران لأنهما لا يعتمدان على سعر الإغلاق أصلاً.

لاحظ انعكاس الحدود: **أعلى** سعر إغلاق يعطي **أعلى** صافٍ و**أقل** خسارة.

### 🖼️ البحث عن صور السيارات

ثلاثة مسارات لإضافة صورة، أولها يعمل دون أي إعداد:

| المسار | يحتاج إعداداً؟ |
|---|---|
| **بحث Wikimedia Commons** (افتراضي) | لا — بلا مفاتيح ولا حصة يومية |
| **لصق رابط صورة** | لا |
| **رفع صورة من الجهاز** | يحتاج تفعيل Firebase Storage |

صور Wikimedia حرة الترخيص وروابطها دائمة، وتُعرض عبر `https` مع
`access-control-allow-origin: *` فيمكن نسخها إلى Storage عند تفعيله.
ابحث بالاسم الإنجليزي للحصول على أدق النتائج (`Toyota Camry 2024`).

**ترقية اختيارية** — لنتائج أدق للموديلات الحديثة جداً، املأ
`public/search-config.js` ببيانات Google Programmable Search:

1. أنشئ محرك بحث على https://programmablesearchengine.google.com
   وفعّل **Search the entire web** و **Image search**، وانسخ Search engine ID
2. فعّل **Custom Search API** من مكتبة واجهات Google Cloud
3. أنشئ مفتاح API وقيّده بـ HTTP referrer على نطاق موقعك، وبـ Custom Search API فقط

عند ملء الحقول يتحوّل المزوّد تلقائياً إلى صور Google بحد 100 بحث يومياً.

## ☁️ إعداد Firebase (التخزين المشترك)

Firebase هو **مصدر البيانات الوحيد** عند ضبطه: الإعدادات وقائمة السيارات
موحّدة لكل الأجهزة، وتعديلها مقصور على المسؤول المسجّل.

### خطوات التفعيل

1. أنشئ مشروعاً على https://console.firebase.google.com
2. **Build → Firestore Database → Create database** (اختر production mode)
3. **Build → Authentication → Get started → Email/Password → Enable**
4. من تبويب **Users** أنشئ حساب المسؤول (بريد + كلمة مرور)
5. **⚙ Project settings → Your apps → Web `</>`** وانسخ `firebaseConfig`
   إلى `public/firebase-config.js`
6. **Firestore Database → Rules** والصق محتوى `firestore.rules` ثم **Publish**
7. امنح المسؤول صلاحية `admin` (خطوة إلزامية — انظر أدناه)

### ⚠ صلاحية admin إلزامية

تسجيل الحسابات في Firebase **مفتوح للعموم افتراضياً**، فأي غريب يستطيع
إنشاء حساب على مشروعك. لذلك تشترط القواعد صلاحية `admin` لا مجرد تسجيل
الدخول. تُمنح هذه الصلاحية عبر custom claim من حساب خدمة:

```js
// accounts:update على Identity Toolkit بحساب خدمة
{ localId: '<uid>', customAttributes: '{"admin": true}' }
```

بدونها لن يستطيع أحد الكتابة — ولا حتى أنت. وبعد منحها يجب **تسجيل الخروج
والدخول من جديد** ليحمل الرمز الصلاحية الجديدة.

**يُنصح إضافياً** بإغلاق التسجيل العام: **Authentication → Settings →
User actions** وأزل تحديد **Enable create (sign-up)**. القواعد تحمي البيانات
بدونه، لكن هذا يمنع تراكم حسابات غريبة على مشروعك.

### نشر القواعد من الطرفية

```bash
npx --yes firebase-tools login
npx --yes firebase-tools deploy --only firestore:rules
```
هذا المسار يُجمّع القواعد محلياً ويطبع رقم السطر لأي خطأ صياغة.

### بنية البيانات

```
config/financial → { ceiling, profitRate, discountedRate, updatedAt, updatedBy }
cars/{carId}     → { name, price, closingType, closingPrice?,
                     closingMin?, closingMax?, imageUrl? }
```
`closingType` إحدى `none` أو `fixed` أو `range`.

صور السيارات تُحفظ في Firebase Storage تحت `cars/`، وقواعدها في
`storage.rules` (تُنشر من **Storage ← Rules**، وتتطلب تفعيل Storage أولاً
من **Build ← Storage ← Get started**).

### ملاحظة على مفاتيح Firebase

قيم `firebaseConfig` **ليست سراً** — Firebase مصمّم لنشرها في كود المتصفح.
الحماية تأتي من `firestore.rules` ومن Authentication، لا من إخفاء المفاتيح.

## 💾 أوضاع التشغيل

يختار التطبيق مصدر البيانات تلقائياً حسب المتاح:

| | Firebase مضبوط | خادم Express | بلا خادم |
|---|---|---|---|
| الإعدادات | Firestore | `config/settings.json` | `localStorage` |
| السيارات | Firestore | `data/cars.json` | `localStorage` |
| المشاركة بين الأجهزة | ✅ موحّدة | موحّدة لمستخدمي الخادم | ❌ كل جهاز على حدة |
| حماية التعديل | Firebase Auth | كلمة مرور محلية | كلمة مرور محلية |

عند غياب Firebase والخادم معاً يظهر تنبيه داخل لوحة الإعدادات يوضّح أن
البيانات محفوظة في هذا المتصفح وحده.

## 🔒 الأمان

**مع Firebase:** كلمات المرور تُدار عبر Firebase Authentication فتُخزَّن
مُجزّأة على خوادم Google ولا تصل إلى المتصفح إطلاقاً. وقواعد `firestore.rules`
تمنع أي كتابة دون تسجيل دخول، وتتحقق من نوع القيم ومداها قبل قبولها.

**تنبيه قائم:** الحسابات نفسها تجري في المتصفح. المسجّل دخوله يستطيع تعديل
السقف والنسب عبر أدوات المطوّر تماماً كما يفعل من الواجهة — الفرق أن القواعد
تمنع **غير المسجّلين** من الكتابة، وتمنع القيم خارج المدى المسموح.

**بدون Firebase:** كلمة مرور الإعدادات حاجز شكلي يمنع الفضول العابر لا أكثر،
وهي محفوظة في `localStorage` لكل متصفح على حدة ولا تُكتب في الكود المصدري.
